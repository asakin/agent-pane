# Agent Pane

Development instructions for coding agents working on this repository. See [README](README.md) for the product overview.

If `AGENTS.local.md` exists at the repository root, read it too. It holds instructions for one machine's checkout and is not committed; not every agent loads it on its own.

## Essential knowledge

- **Documentation:** Use the [README glossary](README.md#terminology). Describe current behavior without treating it as a permanent restriction on future features. Keep feature requirements scoped to their implementation issues, and update descriptive docs when behavior changes.
- **Design proposals:** The changes [CONTRIBUTING.md](CONTRIBUTING.md) names as suited to an RFC (core architecture, protocols, trust boundaries, installer or distribution behavior, product concepts other work builds on) can start as an RFC in [`docs/rfcs/`](docs/rfcs/), written with the [write-rfc skill](tessl-factory/skills/write-rfc/SKILL.md). Other features and fixes need only an issue that says what to build. Implement accepted RFCs in separate focused issues and pull requests.
- **Working directory:** Run every command below from the repository root (pass `--prefix extension` to `npm`, or `cd extension` first).
- **Stack:** Go (version in `go.mod`) for the native host and PTY server; TypeScript, WXT, and `@xterm/xterm` 6 in `extension/` (tested with `node --test tests/*.test.mjs`).
- **Adding a native-messaging RPC method:** define request/response types in `extension/entrypoints/shared/rpc.ts`, forward the method through `sendNative` in `extension/entrypoints/background.ts`, handle it in `internal/cmd/serve.go`, and cover both sides in `extension/tests/nativeRpc.test.mjs` and `internal/cmd/agents_test.go`.
- **Adding an agent definition:** create `agents/<id>/agent.json` and `icon.svg` (or `icon.png`); copy `agents/pi/agent.json` as a starting point.
- **Herdr-core work:** When changing terminal/session architecture, the PTY host, tab lifecycle, agent launching, or terminal attachment to use Herdr behind Agent Pane's own side-panel UI, read `docs/herdr-core-integration.md` first.

## Editing guidance

- **Extension permissions:** Adding permissions or expanding host access in `extension/wxt.config.ts` requires explicit maintainer approval.
- **Generated themes:** `internal/cmd/themes/` is generated by `deno run -A scripts/refresh-themes.ts`. Do not hand-edit files in `internal/cmd/themes/`.
- **Agent definitions:** Follow [agents/README.md](agents/README.md) when adding or enabling a launcher entry.
- **Changelog:** A change a user would notice adds a line under `## [Unreleased]` in [CHANGELOG.md](CHANGELOG.md), in the matching Added, Changed, Fixed or Removed section.

## Commands

Run both check suites before pushing (matching `.github/workflows/ci.yml`):

### Go backend (from repository root)

```sh
gofmt -l .
go vet ./...
go test -race ./...
go build ./...
```

When changing `install.sh`, `install.ps1`, `scripts/place.sh`, `scripts/fetch-herdr-core.sh`, `scripts/herdr-core.lock` or `agent-pane doctor`, also run (it downloads the pinned herdr-core once):

```sh
sh scripts/install_test.sh
```

### Extension (from repository root)

```sh
npm --prefix extension ci
npm --prefix extension run compile
npm --prefix extension test
npm --prefix extension run build
```

## Map

- `main.go`, `internal/cmd/`: Go CLI entry point, native-messaging host (`serve.go`), PTY session environment (`env.go`), page channel, page socket and `agent-pane page` commands (`page.go`, `page_unix.go`), agent catalog loader (`agents.go`), install checks (`doctor.go`), the Windows placing step `agent-pane place` (`place.go`, registry and user `Path` in `winreg_windows.go`), and macOS LaunchAgent spawn (`spawn_darwin.go`). Windows-only code sits in `_windows.go` files.
- `internal/jsonrpc/`, `internal/scrollback/`: JSON-RPC framing and terminal scrollback ring/mode replay.
- `internal/peercred/`: unix socket peer checks (uid, executable, ancestry) for Linux and macOS.
- `internal/herdrcore/`: client for the bundled herdr-core's framed JSON-RPC socket (handshake and generation check, terminal calls, attach streams, events; on Windows the socket is a named pipe, dialled by the small overlapped-I/O client in `pipe_windows.go`) and the private `HC_SESSION=agent-pane` environment. The host uses it for the Durable (preview) terminal backend (`internal/cmd/backend_core.go`). `AGENT_PANE_TEST_HC=<path to the pinned hc> go test ./internal/herdrcore ./internal/cmd` also runs both against a real core.
- `extension/entrypoints/`: WXT extension entry points (`background.ts`, `sidepanel.html`, `options.html`, the injected `page-reader.ts`) and shared terminal/tab/RPC/page modules in `extension/entrypoints/shared/`.
- `extension/tests/`: Node test runner suites (`*.test.mjs`).
- `skills/agent-pane/`: the canonical skill the installer installs for coding agents; see [README](README.md#agent-skill).
- `agents/`: shipped agent definitions and `agents/enabled.json`; see [agents/README.md](agents/README.md).
- `install.sh`, `install.ps1`: the release installer templates (POSIX sh; PowerShell for Windows); `release.yml` publishes them with the version set to the tag, and the repository copies refuse to run. `install.ps1` runs the archive's `agent-pane.exe place`, which does on Windows what `place.sh` does elsewhere; `scripts/install_ps1_test.ps1` tests it on the `go-windows` CI job.
- `scripts/place.sh`, `scripts/instructions.md` (the `~/.config/agent-pane/AGENTS.md` block): place.sh puts a release-shaped folder in place (binary, manifests, LaunchAgent, skill, extension); shipped in every archive. `internal/cmd/doctor.go` checks the same paths, so change both.
- `scripts/dev-install.sh`: builds a checkout and installs it with `place.sh`. `scripts/install_test.sh`: tests for all three.
- `scripts/herdr-core.lock`, `scripts/fetch-herdr-core.sh`: the pinned private herdr-core (`libexec/hc`) each release and dev install carries, with its license files; `place.sh` installs it under `~/.local/share/agent-pane/` and `doctor` checks it against the lock.
